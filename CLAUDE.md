# calofin

AutoLISP tools for pool/spa drafting, plus Blender add-ons and an AutoCAD
palette. Read this before changing anything; `STANDARDS.md` is the full
rulebook for the `.lsp` files themselves.

## Branch convention

**All work in this repository goes on `claude/lisp-consolidation-strategy-9nrc7a`.**

This is the consolidated trunk: it merges what used to be ~29 separate
single-addition branches into one tree where every tool lives side by side.
Unless told otherwise in a specific request, start from this branch and commit
back to it — do not open a fresh `claude/<topic>-<id>` branch per task, and do
not build on any of the older single-tool branches. They are historical; work
added there is invisible to everything else and re-fragments the tree this
branch exists to consolidate.

If a session is handed a different branch name by its setup, that name is
overridden by this convention — check out
`claude/lisp-consolidation-strategy-9nrc7a` and work there instead. An explicit
instruction in the request itself does take precedence.

## Layout

```
blender/    Blender add-ons (DXF import/export, mesh tools)
lisp/       AutoLISP tools, one self-contained file each (the source of truth)
releases/   Dated REV-stamped twins of the lisp/ files, flat, GENERATED
shared/     The loaded-together build on CALOFIN-LIB.lsp (bundle GENERATED)
ui/         The Calofin AutoCAD palette (VB.NET) and its LISP glue
tools/      Dev tooling (release stamping, bundle building, static checks)
tests/      Python test suite - stdlib only, no AutoCAD or Blender needed
```

See `README.md` for the per-tool command tables.

## The tiers a tool moves through

This is the structure everything else protects. A tool exists at up to
four levels of packaging, and they must stay in step:

| Tier | Folder | What it is | Hand-edited? |
| --- | --- | --- | --- |
| draft | `wip/` | being written, no version banner yet, nothing generated from it. Optional — absent until a first draft lands. | yes |
| standalone | `lisp/<tool>/` | one self-contained file that loads alone with APPLOAD. **The development home of all tool logic.** | yes |
| released | `releases/` | dated `REV`-stamped twin of a versioned `lisp/` file, so a loaded routine never changes underfoot | **no — generated** |
| grouped | `shared/` | the same tools rebuilt against one helper library (`cal:` namespace), all loading together in one session | mirrored by hand, bundle generated |

**Work in `lisp/`.** `shared/` is a twin of it, never the place a behavior
change starts. The diff between `lisp/<tool>/FILE.lsp` and
`shared/FILE.lsp` should only ever be the helper copies the library
replaces and the `cal:` call sites.

Inside `shared/`:

- `CALOFIN-ALL.lsp` — **the file to hand anyone**: the whole build
  concatenated, APPLOAD it alone. Generated by `tools/build_shared_bundle.py`.
- `CALOFIN-LIB.lsp` — the helper library. **Only this file may define
  `cal:` symbols.** Never tell anyone to APPLOAD it on its own; it brings
  no tools with it.
- `CALOFIN-LOADER.lsp` — the multi-file alternative, for editing.
- `<TOOL>.lsp` — one twin per `lisp/` tool.

The deprecated acady matcher (`lisp/standards_checker/`) is not carried
into `shared/` and is not expected to be.

## Environment

Nothing to install: the tests run on the Python standard library alone
(`tests/lispvm.py` is a pure-Python AutoLISP interpreter). Variables:

| Variable | Meaning |
| --- | --- |
| `CALOFIN_LISP_ROOT` | which tier the VM tests read. **Unset = `lisp/`, and that is the default every test must keep.** Set it per command, never globally. |
| `PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED` | set by the session-start hook; keep `__pycache__` out of the tree and stream test output |

```
python3 tests/test_pool_runtime.py                          # standalone tier
CALOFIN_LISP_ROOT=shared python3 tests/test_pool_runtime.py # grouped tier
```

Running both is the parity check that keeps the two builds honest.
Exporting `CALOFIN_LISP_ROOT` globally would point the whole suite at
`shared/` and hide a standalone regression — don't.

`.claude/hooks/session-start.sh` runs at the top of every session: it
exports those variables, prints the tier map, and runs the drift check.
`.claude/README.md` has the values for the Claude Code web environment
panels.

## Standards

`STANDARDS.md` at the repo root is the prompt and code standard for the
AutoLISP tools — question wording, canonical keyword sets (corner
treatments are `Square/Radius/Cut/NotGiven`, nothing else), prompt
format, the `cal:` helper roster, and file structure. Every new or
modified `.lsp` follows it; read it before writing one. (It is not
`lisp/standards_checker/`, which matches drawing geometry.)

A **new** tool starts from the library, not from a copy of a sibling:
call the `cal:` helpers rather than pasting a fresh set of local ones.

## Changing a tool

In order, in one commit:

1. Edit the file in `lisp/<tool>/`.
2. Bump its version banner if it has one (`(setq *<tool>-version* "vN.N")`).
3. Mirror the change into `shared/<FILE>.lsp`.
4. Regenerate:
   ```
   python3 tools/release_lisp.py          # releases/ dated twins
   python3 tools/build_shared_bundle.py   # shared/CALOFIN-ALL.lsp
   ```
   Files without a version banner are skipped by the first and reported
   as such; that is expected, not a failure.
5. Check and test (below).

Never hand-edit `releases/` or `shared/CALOFIN-ALL.lsp` — both are
regenerated and your edit will vanish.

## Checks

```
python3 tools/check_standards.py # tiers in step, cal: clean, bundle current
python3 tools/check_lisp.py <f>  # unbalanced parens, undefined funcs/globals
python3 tools/check_scope.py <f> # locals used without being declared
```

`check_standards.py` covers what the other two cannot see, because they
read one file at a time: a `lisp/` tool with no `shared/` twin, a tool
that has started defining `cal:` symbols, two grouped files claiming the
same name, a stale twin in `releases/`, a bundle behind its members. The
session-start hook runs it, so drift shows up when a session opens.

## Tests

Individual scripts under `tests/` — run the ones covering what you
touched (see `README.md` for the full list), plus:

```
python3 tests/test_shared.py    # the whole grouped build in one session,
                                # and the one-file bundle
```

`tests/test_pool_form.py` and `tests/test_spa_form.py` fail on a clean
checkout. That is a known open gap: the palette's `PoolFormView`/`SpaFormView`
were built against an earlier fork of POOL/SPA with a different prompt
sequence, and `lisp/pool/POOL.LSP` / `lisp/spa/SPA.LSP` are the canonical
versions. Don't treat those two failures as something your change caused, and
don't "fix" them by editing the canonical routines to match the palette.
