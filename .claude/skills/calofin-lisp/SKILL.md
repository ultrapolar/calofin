# Changing a calofin AutoLISP tool

The repo's prose is ~260KB across CLAUDE.md, STANDARDS.md and README.md.
Do not read them front to back. This skill is the working subset; the
references below hold the rest, and each says what it answers.

## The one thing to get right

**A tool is four files, not one.** Edit `lisp/`, and the other three
tiers must be regenerated in the SAME commit:

| Tier | Path | Hand-edited? |
| --- | --- | --- |
| standalone | `lisp/<tool>/<TOOL>.lsp` | **yes — all logic starts here** |
| released | `releases/<TOOL>_<date>_REV<n>.lsp` | no — generated |
| grouped | `shared/parts/<TOOL>.lsp` | no — generated by `mirror_shared.py` |
| bundle | `shared/LAZPASS.lsp` | no — generated |

Never hand-edit the bottom three. `shared/parts/LISPLAB.lsp` is the one
exception (its twin's prose differs on purpose); `CALOFIN-LIB.lsp` and
`CALOFIN-LOADER.lsp` are hand-edited sources, not twins.

Only `shared/parts/CALOFIN-LIB.lsp` may define `cal:` symbols. A
`lisp/` file may neither define, call nor set one — it carries its own
copies under its own prefix, and the mirror swaps them.

## Find it without reading it

These replace opening a 9,000-line file. Run them from the repo root.

```bash
S=.claude/skills/calofin-lisp/scripts

# Everything about one tool: files, version, twin, releases, tests, and
# the exact line of every registration site.  Start here.
python3 $S/whereis.py SQUAREUP

# A map of a big file -- every top-level defun/setq with its line number.
python3 $S/lspshow.py --map lisp/pool/POOL.LSP

# One form, with its ;; comment block and line numbers, ready to Edit.
python3 $S/lspshow.py pool:askcorner lisp/pool/POOL.LSP
python3 $S/lspshow.py --cmd SQUAREUP          # the c:SQUAREUP defun
python3 $S/lspshow.py --callers cal:ink       # every call site
```

Tool folders are lowercase, files uppercase (`lisp/squareup/SQUAREUP.lsp`),
with older files lowercase throughout (`lisp/abhd/abhd.lsp`). Each tool
has a `lisp/<tool>/README.md` — cheaper than the root README's 143KB.

## The change pipeline

In order, in one commit:

1. **Edit** `lisp/<tool>/<TOOL>.lsp`. Follow `reference/standards.md`
   before writing a prompt, a knob, a colour or an `*error*` handler.
2. **Bump the version banner** if the file has one:
   `(setq *<tool>-version* "vN.N")`. Do this whenever behaviour changes —
   `releases/` is stamped from it, and a shop pins to that dated twin.
3. **Regenerate every tier below `lisp/`:**
   ```bash
   bash .claude/skills/calofin-lisp/scripts/retier.sh SQUAREUP
   ```
   That runs `mirror_shared.py <TOOL>`, then `release_lisp.py`,
   `build_shared_bundle.py`, and the four UI generators. The `<TOOL>`
   argument is the **twin's file stem**, which is not always the folder
   name — `whereis.py` prints it, or `grep -n "^    '" tools/mirror_shared.py`.
   Files with no version banner are skipped by `release_lisp.py` and
   reported as skipped; that is expected.
4. **Check, scoped** (~23s, instead of `make check`'s ~95s):
   ```bash
   bash .claude/skills/calofin-lisp/scripts/precheck.sh lisp/squareup/SQUAREUP.lsp
   ```
5. **Test what you touched**, then the full run before committing:
   ```bash
   python3 tests/test_squareup.py                           # lisp/ tier
   CALOFIN_LISP_ROOT=shared python3 tests/test_squareup.py  # shared/ tier
   make check && make test
   ```

`CALOFIN_LISP_ROOT` is set **per command, never exported** — exporting it
points the whole suite at `shared/` and hides standalone regressions.

## Rules that fail the build

Each is enforced by a checker; `calofin-checks` decodes the failures.

- **Every command reports its failures.** Five `lzd:` call sites.
  Write the `*error*` handler yourself (it is editorial — what this
  command changed), then `python3 tools/check_lazdiag.py --fix` wires
  the rest. Never hand-write the `lzd:` lines.
- **OSMODE, CECOLOR and CLAYER are borrowed, not taken.** Restored on
  the clean exit *and* from `*error*`, and in the handler they go
  **first**, ahead of anything that can throw. Only list a sysvar in a
  restore table if the tool actually moves it.
- **The load banner is guarded**: `(if (not *calofin-quiet*) (princ ...))`
  as the last form, then `(princ)`.
- **A cue colour says `'auto`; anything left in the drawing takes a plain
  ACI number** — above all a layer record. And a `'fade`/`'guide`
  resolution is **hoisted out of any loop** — it is a COM round trip,
  and `check_perf.py` follows the call graph to find it.
- **Every prompt offers Back**, or gets a line in `tools/back_baseline.txt`
  saying why not.
- **Locals are declared** after ` / ` in the arglist, `*error*` included.

## If you change a prompt

A prompt's wording, keyword set or order is pinned by the form tests.
Run these *first*, and if the form and the routine disagree, **fix the
form, never the canonical routine**:

```bash
python3 tests/test_pool_form.py tests/test_spa_form.py   # (run separately)
python3 tests/test_steps_form.py
python3 tests/test_lazform.py ; python3 tests/test_lazspa.py ; python3 tests/test_lazstep.py
python3 tests/test_back_nav.py
```

## If you change a skill

These skill files are a source tier of their own. `AGENTS.md` at the
repo root — the router every non-Claude agent reads — is **generated**
from them by `tools/gen_agents_md.py`, off the frontmatter, the
reference files and the scripts. So after editing, adding or renaming a
skill:

```bash
python3 tools/gen_agents_md.py
```

`check_standards.py` runs the `--check`, so a stale `AGENTS.md` fails
`make check`. Never hand-edit it; the prose it carries lives in the
generator's `HEADER`/`RULES`/`PIPELINE` constants.

## Branch

All work goes on `claude/lisp-consolidation-strategy-9nrc7a` — the
session-start hook enforces it. Push it at the end of the session; if
the setup named another branch, push that too, at the same commit.
